# StreamShougiBoard

配信 PC の中だけで動く将棋盤です。手元のブラウザで駒を動かすと、OBS のブラウザソースに
出している盤面がそのとおりに動きます。

`stream-shougi-board.exe` を起動すると、アプリ自身が `127.0.0.1` に小さな HTTP/WebSocket サーバーを立てます。
操作画面も OBS 用の盤面も、そこから読み込みます。クラウド、アカウント、外部 DB は使いません。

```text
手元のブラウザ (操作画面)
  → stream-shougi-board.exe / 127.0.0.1:16874
       ├─ 盤面・持ち駒・表示設定の正規状態
       └─ WebSocket → OBS ブラウザソース (/board)
```

実行ファイルは 2 MB ほどの単一 exe で、インストーラーもランタイムも要りません。

## 使い方

1. `stream-shougi-board.exe` を起動したままにする。タスクトレイに常駐し、操作画面が既定のブラウザで開く。
2. OBS に「ブラウザ」ソースを追加し、URL に `http://127.0.0.1:16874/board` を入れる。
   トレイの「OBS 用 URL をコピー」からも取れる。
3. 幅と高さは好きな大きさでよい。盤はその領域いっぱいに広がり、上下左右の中央に載る。
   「背景の濃さ」が 0% なら映像の上に盤と駒台だけが乗る。濃さを上げると、ソースの領域
   いっぱいに半透明の白または黒が敷かれる。
4. 手元の操作画面で駒を動かす。

### 盤の操作

| 操作 | 動き |
| --- | --- |
| マスをクリック | 駒があれば選ぶ。選んだ状態でもう一度押すと外れる |
| 選んでから別のマスをクリック | 動かす。相手の駒があれば取って自分の持ち駒へ |
| 選んでから駒台をクリック | その駒を駒台へ送る |
| 駒台をクリック → 盤をクリック | 持ち駒を打つ |
| 駒をダブルクリック | 成／不成を切り替える |
| 駒を右クリック | 先手／後手を入れ替える |
| ← → | 履歴を戻る・進む |
| Esc | 選択を外す |

合法手の判定はしません。詰将棋を並べたり、途中図を作ったりできるよう、駒は自由に置けます。
玉だけは取れず、駒台にも置けません。

「盤面初期化」で平手、「全駒」で玉以外を全部駒台へ、「空の盤」で何も置かない状態にします。
SFEN の表示・コピー・貼り付けもでき、よく使う局面はブラウザの localStorage へ保存できます。

### OBS 側の見た目

操作画面の「OBS の見た目」から変えられます。変更はその場で配信側へ反映され、次の起動にも残ります。

- 背景の色 (白 / 黒) と濃さ。0% ならソースの領域はすべて透過する
- 駒台の位置: 盤の左右 / 上下
- 外周の余白。盤の大きさはブラウザソースの領域から決まるので、これは縁から空ける px
- 直前の手のハイライト、筋・段の番号、盤の反転 (後手視点)、駒の移動アニメーション
- 選択枠を OBS にも出すか (既定は出さない。手元の選択が配信に映らない)

## ソースからビルド

必要なのは Rust 1.97.1 と Bun 1.4.0、それに `cargo-about 0.9.1` です。

```bash
bun install --frozen-lockfile
bash scripts/install-cargo-about.sh   # 配布バイナリを取って入れる (cargo install でも可)

bun run check        # 版の一致・型・lint・client のテスト
cd app && cargo test # 盤面ロジックとプロトコルのテスト

bun run watch:run    # 開発用。http://127.0.0.1:16874/ が立つ
```

`bun run check` と `cargo build` の前には、OBS 用ページと第三者ライセンスページの生成
(`bun run prepare:assets`) が要ります。`bun run check` は自動で走らせます。生成物は Git 管理せず、
release ビルドが exe へ埋め込みます。debug ビルドでは実行時に `client/static` を読むので、
ページを直しただけならサーバーの再起動は不要です。

配布物は Windows の MSVC ターゲットで作ります。

```bash
cargo build --release --locked --manifest-path app/Cargo.toml   # 今のプラットフォーム向け
```

WSL や Linux からは `bun run build:exe` で Windows 向けにクロスビルドできます
(mingw-w64 が要ります)。動作確認には使えますが、配布物は Release workflow が
`windows-latest` の MSVC ターゲットで作ったものを使ってください。

タスクトレイは Windows でだけ動きます。Linux / macOS ではトレイを飛ばしてサーバーだけ起動するので、
そのまま開発と動作確認ができます。
